# DVBStreamer5 V10.8.486 — CPU upscaling 1080p → 1440p

## Motivation

The SportTV_HD source is **1920×1080**; the operator deliberately
increases the *output* resolution to **2560×1440**. This feature must
remain supported. In V485 at 1440p the encoder worker took ~41–42 ms
per output frame (12 ms software scaling + 29 ms H.264 encoding).
A 25-fps channel only has 40 ms per frame. V485 dropped RAW frames
and accumulated mux/source timing lag. At 1920×1080, the same test
showed 17 ms processing and zero RAW queue drops in the final window.

## Change

The existing **fixed-point separable bilinear** CPU scaler still
determines every pixel, including its source coordinates and rounding.

- Horizontal interpolation: **SSSE3** shuffle and 16-bit fixed-point
  multiply for eligible contiguous 16-pixel source spans.
- Vertical interpolation: **AVX2** for 8 destination pixels per step.
- Both CPU features are chosen using runtime feature detection.
  No global \`-mavx2\` or \`-mssse3\` compiler flags are required.
- Non-x86 systems, older x86 CPUs, downscaling spans, edge pixels and
  remainders use the original scalar method.
- No changes to source codec, CPU encoder preset, audio, PTS/DTS/PCR,
  GOP/IDR, SRT, DVB and access policies.
- CPU upscaling still works without VAAPI, FFmpeg swscale or
  a new package dependency. Hardware-native scaling paths
  continue to take precedence when available.

A standalone native test compares optimized and scalar **pixel
equality** over 1080→1440, 720→1280, 720→576, 1080→720, non-16
pixel dimensions, and randomized 8-bit interpolation weights.

## Verification on the test server

Build from the source root and **do not install on production**:

\`\`\`bash
git switch main && git pull --ff-only origin main
grep kProgramVersion src/AppVersion.h
cmake -S tests/media_core -B build-test-media -DCMAKE_BUILD_TYPE=Release
cmake --build build-test-media --parallel 2
ctest --test-dir build-test-media --output-on-failure
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
\`\`\`

Use the **same** SportTV_HD input at **1920×1080** and output at
**2560×1440**, H.264 25 fps, same preset and bitrate as the V485
test. Measure at least 10 continuous minutes before claiming success.
The following logs identify the path and throughput:

\`\`\`bash
journalctl -u dvbstreamer5.service --since '-10 min' --no-pager -o cat |
  grep -E 'NATIVE VIDEO SCALE|NATIVE VIDEO ENCODE PERF|NATIVE VIDEO DECODE PERF|NATIVE PRIMARY RAW DROP|NATIVE AV CLOCK TRACE|NATIVE AV MUX DROP' |
  grep -E 'stream-1794476735932|NATIVE VIDEO SCALE' | tail -n 100
\`\`\`

Acceptance: sustained 25 fps, no increasing \`raw_drop_total\`, no
increasing \`pes_queue_drop_total\`, no cumulative mux A/V timing
drift and confirmed valid TS/decoder SPS/PPS, continuity counters,
PCR jitter and A/V sound playback.

## Limitations

This commit **does not guarantee** a particular FPS on every CPU:
OpenH264 encoding time, resource contention and input timing may
still exceed frame budget. Local independent synthetic test showed
exact pixels; no real-server 10-minute A/B test was executed by the
code author. If V486 does not sustain 25 fps at 1440p, profile the
scaler and H.264 encoder separately before enlarging queues or
changing PCR.
