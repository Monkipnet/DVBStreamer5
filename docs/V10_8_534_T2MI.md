# DVBStreamer5 V10.8.534 — native T2-MI receive path

Branch: `main`. Changes are test-only until Linux CI and a real receiver
capture confirm service playback. V534 contains the V533 nonfatal CBR queue
backpressure changes; no long-running overflow wait is required to test T2-MI.

## Supported receive pipeline

Outer DVB-S/S2 via `SharedDvbInputPool` or outer network MPEG-TS
(UDP, HTTP, SRT) -> select T2-MI PID -> TS PUSI/pointer and continuity
reassembly -> T2-MI CRC32 -> select T2-MI stream ID -> BBFRAME -> select PLP
-> recover inner 188-byte MPEG-TS -> existing PAT/PMT service remapper,
conditional access, transcoder, HTTP/UDP/SRT/HLS and other native outputs.

The PLP ID is **not** the DVB-S2 MIS/ISI `stream_id` tuner parameter.
Each channel may use its own `input_service_id` while sharing one
satellite transponder and T2-MI PID.

## Native input examples

```text
dvb://satellite?adapter=1&frontend=0&frequency_khz=11785000&symbol_rate=27500&polarity=H&delivery_system=dvb-s2&t2mi_pid=4096&t2mi_stream=0&t2mi_plp=0
udp://239.20.20.20:1234#t2mi_pid=4096&t2mi_stream=0&t2mi_plp=0
http://192.0.2.100:8080/ts#t2mi_pid=4096&t2mi_stream=0&t2mi_plp=0
srt://192.0.2.100:9000?mode=caller#t2mi_pid=4096&t2mi_stream=0&t2mi_plp=0
```

For standard transport inputs, `t2mi_pid` is **required** to enable
decoding. `t2mi_stream` can be 0..7 and `t2mi_plp` can be 0..255.
Omitting PLP selects the first decoded PLP, but a fixed PLP is recommended
for stable services. Select the inner program with the channel's
`input_service_id` (PNR/SID), not with `t2mi_plp`.

## Astra conversion

Astra Lua 4.4 and JSON tuner references accept:
```text
dvb://a001#pnr=100&t2mi=0&t2mi_pid=4096&plp=0
t2mi://a001#pnr=100&t2mi=0&t2mi_pid=4096&plp=0
```

Here `a001` must reference a satellite `dvb_tune` entry in the same
source configuration. The converted internal URI references the real
`adapter`, `frontend`, frequency and LNB, not the Astra symbolic ID.
Astra virtual MPTS adapters whose underlying sources are not a resolvable
satellite tuner still require manual mapping. Import remains additive
and **auto_start=false**, and never migrates CAM secrets.

## Diagnostic checks

```bash
journalctl -u dvbstreamer5.service -f -o cat | grep --line-buffered 'NATIVE T2MI STATUS'
```

Confirm rising `mi_packets`, `bbframes` and `inner_packets`, while
`crc_errors` and `cc_errors` remain stable. Selected PLP is reported
as `plp`; `-1` means none recovered.

## Limitations to validate

The recovery engine supports TS Normal Mode and High Efficiency Mode
without ISSY or Null Packet Deletion (NPD). BBFRAMEs using GSE,
ISSY/NPD and unsupported UPL layouts are rejected; not misinterpreted as
working MPEG-TS. BBHEADER and user-packet CRC-8 validation and all advanced
BBFRAME extensions are not yet covered. The inner transport output has
not been verified against a production satellite/PLP capture, so
"complete T2-MI coverage" cannot yet be claimed.

## Build and test from the source root

```bash
git switch main
git pull --ff-only origin main
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release --parallel 2
ctest --test-dir build-release -R 't2mi_inner_ts|external_config_transfer' --output-on-failure
ctest --test-dir build-release --output-on-failure
bash scripts/make_portable_linux_bundle.sh --build-dir build-release --with-oscam --archive
(cd dist && sha256sum -c DVBStreamer5-10.8.534-linux-x86_64.tar.gz.sha256)
```

Only install after successful tests and a maintenance window. Back up
`/etc/dvbstreamer5` and do not disturb an active production tuner.
